## 1. 文档说明

### 1.1 编写目的

本文档定义 Dzc-RenderEngine 的业务目标、产品范围、功能需求、非功能需求、技术约束、阶段划分及验收标准，作为后续架构设计、开发实现、测试验证和版本验收的统一依据。

本文档同时覆盖以下两个开发阶段：

- **Phase 1：OpenGL 基础渲染阶段**，用于快速验证点云加载、渲染管线、可视化效果和基础交互能力。
- **Phase 2：Vulkan 高性能迁移阶段**，用于降低 CPU 和驱动开销，增加多线程命令录制、显存管理、层次化 LOD，以及 CUDA-Vulkan 零拷贝互操作能力。

两个阶段分别定义范围与验收标准。Phase 2 不得绕过 Phase 1 直接实现，项目必须遵循“先 OpenGL 实现逻辑，后 Vulkan 迁移优化”的演进路线。

### 1.2 需求措辞

本文档使用以下措辞表示需求约束强度：

- **必须**：当前阶段的强制要求，不满足则该需求不能通过验收。
- **应当**：原则上需要满足；若无法满足，必须记录原因、影响及替代方案。
- **可以**：可选能力，不作为当前阶段通过验收的必要条件。
- **待确定**：现有输入不足，禁止在实现中擅自决定，需在获得补充材料或确认后更新需求。

### 1.3 参考输入

本文档依据以下输入编制：

1. 用户提供的业务背景与技术栈描述。
2. 项目根目录 `agent.md` 中的架构、编码、技术边界及交付规范。
3. 用户对项目名称、文档范围、项目性质及各项建议需求的确认。

### 1.4 术语与缩写

| 术语 | 含义 |
|---|---|
| 点云 | 由大量三维空间点及其附加属性组成的数据集合 |
| GIS | Geographic Information System，地理信息系统 |
| LOD | Level of Detail，根据观察距离或屏幕贡献选择不同细节层级 |
| VAO | OpenGL Vertex Array Object |
| VBO | OpenGL Vertex Buffer Object |
| SSBO | OpenGL Shader Storage Buffer Object |
| FPS | Frames Per Second，每秒渲染帧数 |

| Engine | 与 Qt UI 解耦的点云渲染核心 |
| UI | 基于 Qt 构建的桌面图形界面层 |

## 2. 项目概述

### 2.1 项目名称

项目正式名称为 **Dzc-RenderEngine**。

当前仓库目录名为 `Dzc-RengerEngine`，但产品、代码文档和对外说明中应统一使用 `Dzc-RenderEngine`。本需求不要求在当前阶段修改仓库目录名。

### 2.2 业务背景

传统桌面点云软件在渲染亿级激光雷达点云时，通常面临以下问题：

- 海量点数据对系统内存和 GPU 显存造成较大压力；
- 直接绘制全部点会导致帧率下降，影响相机漫游和参数调整；
- OpenGL 驱动层状态管理及单线程提交容易形成 CPU 侧瓶颈；
- 计算预处理结果在 CPU、CUDA 与图形 API 之间反复复制会增加延迟和内存带宽消耗；
- UI、数据处理和渲染逻辑耦合会增加后续迁移与维护成本。

Dzc-RenderEngine 旨在通过分阶段实现与后端迁移，形成一套高性能、可扩展且与 UI 解耦的海量 GIS 点云可视化引擎。

### 2.3 核心目标

项目的核心目标如下：

1. 建立能够加载、显示和交互浏览海量点云数据的跨平台桌面应用基础架构。
2. 在 Phase 1 使用 OpenGL 4.5 验证完整渲染链路和基础可视化效果。
3. 在 Phase 2 将核心渲染能力迁移至 Vulkan，降低 CPU Overhead，并支持多线程命令录制。
4. 使用分块、视锥体剔除、显存预算管理和层次化 LOD 支撑亿级点云浏览。
5. 使用 CUDA 完成简单的 GPU 端预处理，并通过 CUDA-GL/Vulkan Interop 避免计算结果经 CPU 内存中转。
6. 使用 Qt 5.15.19 提供数据加载、参数调整、状态显示和渲染视图控制功能。
7. 保持 Engine 与 Qt UI 解耦，使 OpenGL 与 Vulkan 后端可以在统一上层接口下独立演进。

### 2.4 成功标准

项目整体成功至少需要满足以下条件：

- Phase 1 能够在 Windows 10/11 64 位环境下完成千万级点云加载、显示和连续视图交互。
- Phase 2 能够在待确定的基准硬件上支持至少 1 亿点数据集的按需加载与实时浏览。
- 在 1920×1080 分辨率、相机持续运动的验收场景下，Phase 2 平均帧率不低于 30 FPS，优化目标为 60 FPS。
- CUDA 计算结果能够通过图形互操作资源直接进入渲染管线，不经 CPU 内存中转。
- UI 不直接依赖 OpenGL/Vulkan/CUDA 资源句柄，Engine 不依赖 Qt UI 类型。
- OpenGL 与 Vulkan 后端使用统一的上层生命周期接口，并可在程序启动时选择。

## 3. 项目范围

### 3.1 范围内功能

本项目包含以下能力：

- 本地点云文件加载；
- 点云数据解析和基本属性检查；
- 点云分块及基础空间边界计算；
- OpenGL 4.5 点云渲染；
- Vulkan 点云渲染；
- 基于数据块的视锥体剔除；
- Phase 2 层次化 LOD；
- Phase 2 异步分块加载和显存预算管理；
- 点大小、背景色和着色模式调整；
- 相机或视图控制事件接入；
- FPS、点数量、可见点数量和运行状态显示；
- CUDA 坐标转换、颜色计算和无效点过滤；
- CUDA-OpenGL 与 CUDA-Vulkan 资源互操作；
- Qt 桌面 GUI；
- OpenGL/Vulkan 后端启动时选择；
- 错误提示、运行日志和性能测试记录。

### 3.2 范围外功能

以下功能不属于当前项目范围：

- 点云配准、修补、曲面重建等通用点云处理；
- 深度学习推理或训练；
- 复杂 GIS 坐标系转换；
- 在线地图、网络下载或远程点云流；
- 通用图像处理；
- 复杂点云下采样算法；
- 编辑、删除或人工标注点云；
- 多人协同；
- 云服务或 Web 端部署；
- 程序运行过程中动态切换 OpenGL/Vulkan 后端；
- macOS 平台支持；
- 当前版本强制支持 LAS/LAZ 文件格式。

LAS/LAZ 可作为未来扩展候选，但在新增正式需求和确定读取依赖前，不属于 Phase 1 或 Phase 2 的强制验收范围。

### 3.3 用户类型

本项目为个人开源项目，主要面向以下用户：

- **点云数据浏览用户**：加载本地点云并调整显示参数、观察数据和性能状态。
- **开发者/贡献者**：构建项目、扩展读取能力、优化渲染后端或增加平台支持。
- **性能测试人员**：使用固定数据集、硬件和测试场景记录性能结果。

## 4. 总体架构要求

### 4.1 分层架构

系统必须至少划分为以下逻辑层：

1. **Qt UI 层**
   - 负责主窗口、菜单、工具栏、参数控件、状态展示和用户输入事件采集。
   - 将窗口尺寸和鼠标、键盘等事件转换为 Engine 可理解的抽象输入。
   - 不负责点云渲染算法和 GPU 资源管理。

2. **Engine 公共接口层**
   - 对 UI 暴露最小化、后端无关的生命周期和控制接口。
   - 负责调度数据、相机、场景和渲染后端。
   - 不向 UI 暴露 `GLuint`、`VkCommandBuffer`、CUDA 资源句柄等底层对象。

3. **数据与场景层**
   - 负责点云读取、属性检查、分块、边界信息、空间层次和加载状态。
   - Phase 2 负责异步调度和内存/显存驻留策略。

4. **渲染后端层**
   - Phase 1 实现 OpenGL 4.5 后端。
   - Phase 2 实现 Vulkan 后端。
   - 两个后端遵循统一的上层契约，但内部资源和同步实现相互独立。

5. **CUDA 计算与互操作层**
   - 负责已确认的简单 GPU 预处理。
   - 封装 CUDA 与 OpenGL/Vulkan 的注册、映射、同步和解除注册流程。

### 4.2 依赖方向

系统依赖方向必须满足：

```text
Qt UI -> Engine Interface -> Scene/Data + Render Backend
                                  |
                                  +-> CUDA/Interop
```

必须遵循以下约束：

- UI 可以依赖 Engine 公共接口；
- Engine 不得依赖具体 UI 控件；
- Engine 类不得继承 `QWidget`、`QOpenGLWidget`、`QWindow` 或 `QObject`；
- 数据层不得依赖 Qt UI；
- OpenGL 后端不得成为 Vulkan 后端的运行时依赖，反之亦然；
- PCL 只能用于 I/O 读取，不得用于渲染实现。

### 4.3 Engine 接口约束

Engine 对外应仅暴露必要的生命周期和业务控制接口，包括但不限于：

- `init()`：初始化 Engine 及已选择的渲染后端；
- `update()`：更新场景、输入和帧状态；
- `render()`：执行一帧渲染；
- `resize()`：更新渲染目标尺寸；
- 点云加载、取消加载和卸载接口；
- 后端无关的渲染参数设置接口；
- 后端无关的输入事件接口；
- 状态和错误查询接口。

具体接口签名属于架构设计阶段内容，但不得违反以下要求：

- 不得向调用方暴露底层图形 API 资源 ID 或命令缓冲对象；
- 公共头文件仅包含公共接口及必要公共数据结构；
- 私有成员、辅助函数和工具类实现必须隐藏在 `.cpp` 文件中，优先使用 Pimpl；
- GPU 资源必须由 RAII 包装对象管理；
- 不得使用裸指针手动管理资源生命周期。

## 5. 公共功能需求

本章定义两个阶段共同适用或最终必须具备的功能。

### 5.1 应用启动与后端选择

#### FR-COM-001 启动渲染后端选择

系统必须支持在程序启动时选择 OpenGL 或 Vulkan 渲染后端。

验收条件：

- 后端可以通过启动参数或启动配置选择；具体形式在详细设计阶段确定。
- 选择 OpenGL 时不得初始化 Vulkan 渲染设备。
- 选择 Vulkan 时不得依赖 OpenGL 渲染资源。
- 后端选择失败时，系统必须显示明确错误，不得静默切换并掩盖问题。
- 本需求不要求程序运行期间动态切换后端。

#### FR-COM-002 运行环境检查

系统必须在初始化阶段检查所选后端需要的运行环境。

至少包括：

- OpenGL 版本是否达到 4.5；
- Vulkan 实例、物理设备、队列族和所需扩展是否可用；
- CUDA 功能启用时，是否存在兼容的 NVIDIA GPU 和 CUDA 运行环境；
- 图形后端与 CUDA 设备是否满足互操作条件。

环境不满足时，系统必须给出可理解的错误信息。

### 5.2 点云文件加载

#### FR-DATA-001 文件格式

首版必须支持以下本地点云文件格式：

- PCD；
- PLY。

字段要求：

- XYZ 坐标为必需字段；
- RGB 为可选字段；
- intensity 为可选字段；
- 法线不是当前强制字段；
- classification 不是当前强制字段。

当文件缺少 XYZ、格式损坏或字段类型不受支持时，系统必须拒绝加载并提示原因。

#### FR-DATA-002 文件选择

Qt UI 必须提供本地文件选择入口。文件选择器应当根据当前支持格式设置过滤条件。

#### FR-DATA-003 加载进度

系统必须显示点云加载状态和进度。加载过程不得长时间阻塞 Qt UI 事件循环。

验收条件：

- 加载期间主窗口可以响应移动、最小化和取消操作；
- UI 能区分未开始、加载中、已完成、已取消和失败状态；
- 加载失败时显示错误摘要，并在日志中记录诊断信息。

#### FR-DATA-004 取消加载

用户必须能够取消尚未完成的点云加载任务。

取消后：

- 系统应当尽快停止后续解析或上传工作；
- 不完整数据不得被标记为可正常渲染的数据集；
- 已分配的临时 CPU/GPU 资源必须安全释放；
- UI 必须恢复到可继续选择文件的状态。

#### FR-DATA-005 数据统计

成功加载后，系统必须至少提供以下信息：

- 文件路径或文件名；
- 总点数；
- 已识别的点属性；
- 点云包围盒；
- CPU 内存和 GPU 显存使用量的可获取统计。

若某项内存统计无法由平台可靠提供，应显示“不可用”，不得伪造数值。

#### FR-DATA-006 大坐标处理

系统必须保留输入点的原始坐标语义，并使用局部原点平移或等效方案降低大绝对坐标在 GPU 单精度渲染中的精度损失。

本需求不包括不同 GIS 坐标参考系之间的转换。

### 5.3 点云显示

#### FR-REN-001 基础绘制

系统必须将有效点作为点图元绘制到渲染视图中，并正确应用当前视图和投影变换。

#### FR-REN-002 点大小调整

用户必须能够在 UI 中调整点的显示大小。参数变更后应在后续帧生效，无需重新加载点云。

具体最小值、最大值和步长由详细设计确定，并应根据硬件支持范围进行限制。

#### FR-REN-003 着色模式

系统必须支持以下着色模式：

1. 原始 RGB；
2. 固定单色；
3. 按高度着色；
4. 按 intensity 着色。

行为要求：

- 当数据不包含 RGB 时，原始 RGB 模式必须不可选或自动提示不可用；
- 当数据不包含 intensity 时，intensity 模式必须不可选或自动提示不可用；
- 按高度着色必须依据当前数据集的高度范围生成稳定的颜色映射；
- 切换着色模式不得要求重新读取源文件。

#### FR-REN-004 背景颜色

用户必须能够通过 UI 设置渲染视图背景颜色，设置结果应在后续帧生效。

#### FR-REN-005 视图尺寸变化

系统必须正确处理渲染窗口尺寸和 DPI 变化，更新渲染目标、视口及投影参数，避免画面拉伸或访问失效资源。

### 5.4 视图与输入交互

#### FR-CAM-001 输入事件接入

Qt UI 必须能够将鼠标、键盘、滚轮、窗口焦点和 ResetRequest 输入转换为后端无关的 Engine 输入事件。QT-005 固定像素坐标按视口左上角原点归一化到 `[0,1]`，左/右键编码为 `0/2`，Shift/Ctrl/Alt/Meta 修饰位为 `1/2/4/8`；未定义按钮和未覆盖 Qt 键必须同步返回参数错误且不得入队。

#### FR-CAM-002 透视轨道相机交互

系统必须提供后端无关的透视轨道相机：右手坐标、世界 `+Y` 向上、相机本地 `-Z` 指向 orbit target。它不支持正交模式、键盘控制、惯性或时间驱动运动。

- `PointerMove.valueX/valueY` 使用相对视口左上角的 `[0, 1]` 绝对归一化坐标；左键（`PointerButton.code == 0`）执行受约束轨迹球旋转，右键（`code == 2`）沿当前屏幕 `right/up` 平面平移 target；任意按钮释放结束当前拖拽。
- 轨迹球使用球面/双曲面连接阈值 `1/sqrt(2)` 和 270°/单位归一化屏幕长度的灵敏度；旋转不得使旋转后的本地 `+Z` 世界方向低于 `-1e-6`，必要时以 16 次二分限制最大合法旋转。
- 滚轮正负号分别将距离乘 `0.9` 或 `1.1`，交互距离钳制到 `[0.1, 1000]`；不按滚轮幅度累计。
- 失焦取消拖拽；未知鼠标按钮、非有限滚轮值、非有限或越界指针坐标必须以可诊断参数错误失败且不改变状态。控制器每次有效更新都按场景 Bounds 包围球刷新裁剪面：`near=max(0.001, 0.9*max(s-r,0))`、`far=max(near*2, 1.1*(s+r))`，其中 `s` 是相机到 Bounds 中心的距离，`r` 是 Bounds 半对角线长度；详细推导见 `docs/design/cameraInteractionDesign.md`。
- QT-005 已确定 Qt 键码仅使用有限稳定 Qt Key → USB HID 映射，输入通过公共 `SubmitInputCommand` 转发；Engine 当前只消费输入命令，不注入或调用 Camera Controller。Controller 注入、所有权和线程模型仍属于后续任务；不得通过公共输入类型绑定 Qt 或 Vulkan。

#### FR-CAM-003 视图重置入口

UI 必须预留视图重置入口。直接 reset 或 `ResetRequest` 最终使用当前场景 `Bounds3d` 的中心作为 orbit target，清除旋转、平移和拖拽状态，并按 Bounds 包围球半径的 1.05 倍、当前 aspect 和 45° 垂直 FOV 自动框选。自动框选距离可以大于 1000；1000 上限仅适用于滚轮交互。

`ResetRequest` 在下一次有效 `update(deltaSeconds, sceneBounds)` 延迟执行；控制器尚未获得有效视口尺寸时 reset 必须失败且不产生部分状态。尺寸变化后不自动重新框选，保持用户当前视角。

### 5.5 可见性与层次调度

#### FR-VIS-001 数据块边界

系统必须能够将点云组织为可独立判断可见性的数据块，并维护每个数据块的空间边界。

#### FR-VIS-002 分块视锥体剔除

系统必须以数据块为粒度执行视锥体剔除，不得仅对整个点云执行一次整体可见性判断后无条件绘制全部数据块。

#### FR-VIS-003 可见点统计

系统必须提供当前帧或最近稳定采样周期内的可见数据块数量和可见点数量统计。

统计口径必须在性能报告中说明；若为估算值，应明确标识。

### 5.6 CUDA 预处理

#### FR-CUDA-001 CUDA 功能开关

UI 必须提供 CUDA 预处理启用/禁用控制，或在启动配置中提供等效开关。

当系统不存在可用 CUDA 环境时：

- 应允许禁用 CUDA 功能后运行基础渲染；
- CUDA 相关控制应显示为不可用；
- 系统不得因可选 CUDA 功能缺失而阻止非 CUDA 渲染后端启动，除非所选配置明确要求 CUDA。

#### FR-CUDA-002 预处理范围

当前 CUDA 简单预处理必须限定为：

- 坐标变换或局部原点转换；
- 高度或 intensity 等显示颜色计算；
- NaN、Infinity 或其他明确无效点过滤。

复杂下采样、点云配准、特征提取和深度学习不属于当前需求。

#### FR-CUDA-003 互操作零拷贝

CUDA 预处理结果必须通过 CUDA-OpenGL 或 CUDA-Vulkan 互操作资源直接供对应渲染后端使用，不得为了渲染而将计算结果复制回 CPU 内存再上传至 GPU。

“零拷贝”仅约束 CUDA 计算结果到渲染管线之间的路径，不表示磁盘读取、文件解析和首次 GPU 上传全过程无复制。

#### FR-CUDA-004 同步正确性

系统必须正确处理 CUDA 与图形队列之间的资源所有权和同步，保证：

- 图形管线不会读取尚未完成写入的数据；
- CUDA 不会覆盖仍被图形管线使用的数据；
- 资源销毁前相关 GPU 工作已经安全完成；
- 错误或取消路径不会遗留已注册的互操作资源。

### 5.7 GUI 与状态反馈

#### FR-UI-001 主窗口

应用必须使用 Qt 5.15.19 和 `QMainWindow` 构建主窗口。

#### FR-UI-002 渲染视图容器

- Phase 1 必须使用 `QOpenGLWidget` 承载 OpenGL 渲染视图；
- Phase 2 必须使用 `QWindow` 封装 Vulkan Surface，并嵌入 Qt 界面。

Qt 容器仅负责窗口承载和事件转发，不得包含核心渲染算法。

#### FR-UI-003 参数控制

GUI 必须提供以下控制项：

- 打开点云文件；
- 取消加载；
- 点大小调整；
- 着色模式选择；
- 固定点颜色设置；
- 背景颜色设置；
- CUDA 预处理开关或状态；
- 视图重置入口；
- 相机相关参数区域，其最终字段待 FR-CAM-002 确定。

#### FR-UI-004 状态显示

GUI 必须显示以下运行状态：

- 加载状态和进度；
- 当前渲染后端；
- FPS；
- 数据集总点数；
- 当前可见点数量；
- CUDA 是否可用及是否启用；
- 当前错误或警告摘要。

#### FR-UI-005 运行日志

系统必须记录关键运行事件，包括：

- 应用和后端初始化；
- GPU/驱动能力检测摘要；
- 文件加载开始、结束、取消和失败；
- GPU 资源创建失败；
- CUDA/图形互操作注册与同步错误；
- 可恢复或不可恢复错误。

日志不得包含无意义的逐帧重复信息，以免影响性能或淹没有效诊断信息。

### 5.8 性能统计

#### FR-STAT-001 FPS 统计

系统必须统计并显示 FPS。统计应使用稳定的时间窗口或平滑策略，避免仅显示单帧倒数造成数值剧烈跳动。

#### FR-STAT-002 性能数据记录

性能测试构建或诊断模式应能够记录：

- 平均 FPS；
- 帧时间；
- 已提交绘制的点数量或估算数量；
- 可见数据块数量；
- CPU 内存与 GPU 显存使用情况；
- 数据加载耗时；
- 测试后端、分辨率、数据集和硬件环境。

低帧率百分位指标的具体阈值在基准硬件确定后补充。

## 6. Phase 1：OpenGL 基础渲染需求

### 6.1 阶段目标

Phase 1 用于验证从文件读取到屏幕显示的完整链路，并建立可迁移的 Engine、数据层、UI 层和渲染后端边界。该阶段重点是功能正确性和架构可迁移性，不要求达到最终亿级点云性能。

### 6.2 Phase 1 范围

Phase 1 必须实现：

- Qt 5.15.19 主窗口；
- `QOpenGLWidget` 渲染视图；
- OpenGL 4.5 上下文及能力检查；
- PCD/PLY 文件读取；
- XYZ、可选 RGB 和可选 intensity 属性处理；
- 一次性加载和基础数据分块；
- VAO/VBO/SSBO 数据组织与绘制；
- 四种已定义着色模式；
- 局部原点大坐标处理；
- 基于数据块的视锥体剔除；
- 点大小和背景色调整；
- FPS、总点数及可见点数量显示；
- CUDA 简单预处理；
- CUDA-OpenGL Interop；
- 加载进度、取消、错误提示和日志；
- 后端无关的 Engine 接口；
- 相机输入事件接入，但最终交互规则待参考源码确定。

### 6.3 OpenGL 实现约束

#### FR-GL-001 OpenGL 版本

OpenGL 后端必须使用 OpenGL 4.5 核心特性，不得依赖已弃用的固定功能管线。

#### FR-GL-002 GPU 数据对象

OpenGL 后端必须根据用途使用 VAO、VBO 和/或 SSBO 组织点云数据。具体布局由详细设计决定，但必须避免逐点 CPU 绘制调用。

#### FR-GL-003 Shader

点云坐标变换、点绘制和着色必须通过现代 Shader 管线完成。Shader 编译或链接失败时，系统必须输出可定位的错误日志。

#### FR-GL-004 CUDA-OpenGL 互操作

启用 CUDA 时，可由 CUDA 写入的 OpenGL 缓冲资源必须通过正式互操作机制注册和映射。不得使用“CUDA 写回 CPU，再由 OpenGL 上传”的方式冒充互操作。

### 6.4 Phase 1 验收标准

Phase 1 必须满足下列验收条件：

| 编号 | 验收项 | 通过条件 |
|---|---|---|
| AC-P1-001 | 构建 | 在规定 Windows 开发环境中使用 CMake 成功配置并构建 |
| AC-P1-002 | 后端初始化 | 成功创建 OpenGL 4.5 核心上下文，并显示明确的 GPU/版本信息 |
| AC-P1-003 | 文件读取 | 能成功加载包含 XYZ 的有效 PCD 和 PLY 文件 |
| AC-P1-004 | 错误处理 | 损坏文件、缺失 XYZ 或不支持字段不会导致崩溃，并给出错误信息 |
| AC-P1-005 | 数据规模 | 在基准硬件确定后，使用至少 1,000 万点测试数据完成加载和显示 |
| AC-P1-006 | 基础渲染 | 点云可见，视图和投影变换正确，窗口缩放后无明显拉伸或资源错误 |
| AC-P1-007 | 着色 | 原始 RGB、固定单色、按高度、按 intensity 四种模式按属性可用性正确工作 |
| AC-P1-008 | 分块剔除 | 移出视锥体的数据块不被提交绘制，可通过统计或调试视图验证 |
| AC-P1-009 | UI 响应 | 加载期间窗口保持响应，并可取消加载 |
| AC-P1-010 | 状态统计 | 能显示 FPS、总点数、可见点数量和加载状态 |
| AC-P1-011 | CUDA 降级 | 无 CUDA 环境时可禁用 CUDA 并继续使用 OpenGL 基础渲染 |
| AC-P1-012 | CUDA 互操作 | 有兼容环境时，CUDA 结果通过 CUDA-OpenGL Interop 直接供 OpenGL 使用 |
| AC-P1-013 | 架构边界 | Engine 不继承 Qt UI 类，UI 不获取 OpenGL 资源 ID |
| AC-P1-014 | 相机需求 | 在参考源码尚未提供时，只验收输入抽象和事件传递，不验收具体按键及相机模型 |

Phase 1 暂不规定固定加载秒数或强制 FPS 数值，但必须在性能测试报告中记录实际结果、数据集、分辨率和硬件环境。

## 7. Phase 2：Vulkan 高性能迁移需求

### 7.1 阶段目标

Phase 2 在保留上层功能和统一 Engine 契约的基础上，将核心渲染管线迁移到 Vulkan，并增加支持亿级点云所需的并行提交、按需数据调度、显存预算和 LOD 能力。

### 7.2 Phase 2 范围

Phase 2 必须实现：

- Vulkan 实例、物理设备、逻辑设备、队列和 Surface 管理；
- 基于 `QWindow` 的 Vulkan 渲染窗口；
- Swapchain 及窗口变化重建；
- 点云 Vulkan Buffer 和显存管理；
- 多线程命令录制；
- Secondary Command Buffers；
- Pipeline Cache；
- 分块异步加载和 GPU 上传；
- CPU 内存和 GPU 显存预算管理；
- 层次化空间结构与 LOD；
- 分块视锥体剔除；
- CUDA-Vulkan Interop；
- 同步、资源所有权和异常恢复；
- 启动时选择 OpenGL 或 Vulkan 后端；
- 不低于 Phase 1 的公共显示和 UI 功能。

### 7.3 Vulkan 实现需求

#### FR-VK-001 Vulkan 初始化

Vulkan 后端必须完成实例、物理设备、逻辑设备、队列和交换链初始化，并记录所选择设备和关键能力。

#### FR-VK-002 Swapchain 生命周期

窗口大小或 Surface 状态变化导致 Swapchain 失效时，系统必须安全重建相关资源，不得继续使用失效的图像、视图或帧缓冲资源。

#### FR-VK-003 多线程命令录制

Vulkan 后端必须使用多个工作线程并行录制可独立处理的数据块绘制命令。线程数量和任务划分策略由详细设计确定。

实现必须避免多个线程无同步地写入同一命令池或其他要求外部同步的 Vulkan 对象。

#### FR-VK-004 Secondary Command Buffers

数据块或渲染批次的绘制工作必须使用 Secondary Command Buffers 录制，并由 Primary Command Buffer 组织和提交。

#### FR-VK-005 Pipeline Cache

系统必须创建并使用 Vulkan Pipeline Cache。若保存到磁盘，缓存失效或不兼容时必须能够安全回退并重新生成，不得导致程序无法启动。

#### FR-VK-006 显存管理

Vulkan 后端必须封装显存分配和释放，不得在业务层散布裸 `VkDeviceMemory` 生命周期操作。

显存管理至少需要支持：

- 点云块缓冲资源；
- 上传暂存资源；
- 内存类型选择；
- 对齐要求；
- 延迟销毁或帧同步后的安全释放；
- 显存预算统计。

#### FR-VK-007 异步上传

点云数据块的文件读取、CPU 准备和 GPU 上传必须允许流水化执行，不得要求每加载一个数据块都阻塞整个渲染循环直到设备空闲。

#### FR-VK-008 避免全局空闲等待

正常逐帧渲染和数据上传流程中，不应使用 `vkDeviceWaitIdle` 作为常规同步手段。设备全局等待仅可用于初始化失败清理、交换链重建的必要路径或程序关闭等低频场景，并应在实现中说明原因。

### 7.4 Phase 2 数据调度与 LOD

#### FR-LOD-001 层次化空间组织

系统必须使用层次化空间结构组织点云数据块，使可见性判断和 LOD 选择不需要逐点遍历完整数据集。

本文档不指定八叉树或其他具体结构，具体方案在架构设计阶段确定。

#### FR-LOD-002 LOD 选择

系统必须根据观察条件选择合适的点云细节层级。选择依据至少应考虑数据块边界与当前相机/视图的关系，可以进一步考虑屏幕空间误差或投影尺寸。

#### FR-LOD-003 渐进显示

当完整细节尚未加载时，系统应优先显示可用的较低细节层级，避免在长时间加载期间保持空白画面。

#### FR-LOD-004 显存预算

系统必须支持可配置或自动计算的 GPU 显存预算，并在预算范围内管理数据块驻留。

当预算不足时：

- 应优先保留当前可见或高优先级数据块；
- 应淘汰低优先级、长期不可见的数据块；
- 不得依赖 GPU 分配失败作为正常淘汰机制；
- 不得因单个数据块无法驻留而导致整个程序崩溃。

#### FR-LOD-005 CPU 内存预算

系统应当对 CPU 侧缓存设置预算或上限，并避免无限保留已读取但当前不需要的数据块。

### 7.5 CUDA-Vulkan 互操作

#### FR-VKCUDA-001 外部资源互操作

CUDA 计算使用的 Vulkan 缓冲资源必须通过兼容的外部内存机制共享，使 CUDA 结果可以直接被 Vulkan 渲染管线读取。

#### FR-VKCUDA-002 外部同步

CUDA 与 Vulkan 之间必须使用兼容的外部信号量或等效 GPU 同步机制协调读写，不得将 CPU 轮询或设备全局等待作为正常逐帧同步方案。

#### FR-VKCUDA-003 设备匹配

系统必须验证 CUDA 设备与 Vulkan 物理设备是否对应且支持互操作。无法匹配时必须禁用互操作并给出明确说明，不得在不同物理 GPU 间错误共享资源。

### 7.6 Phase 2 验收标准

Phase 2 必须满足下列验收条件：

| 编号 | 验收项 | 通过条件 |
|---|---|---|
| AC-P2-001 | Vulkan 构建与启动 | 使用 CMake 成功构建，Vulkan 后端可通过启动配置独立启动 |
| AC-P2-002 | 功能等价 | Phase 1 已验收的公共加载、显示、参数和状态功能在 Vulkan 后端可用 |
| AC-P2-003 | Swapchain | 窗口缩放、最小化和恢复时不崩溃，Swapchain 能正确重建 |
| AC-P2-004 | 多线程录制 | 性能或诊断记录能证明多个工作线程参与命令录制 |
| AC-P2-005 | Secondary Command Buffers | 数据块或批次绘制命令通过 Secondary Command Buffers 组织 |
| AC-P2-006 | Pipeline Cache | Pipeline Cache 被实际创建和使用，失效缓存可安全重建 |
| AC-P2-007 | 异步调度 | 数据块加载和上传期间渲染循环保持运行，界面不冻结 |
| AC-P2-008 | 显存预算 | 在人为降低预算的测试中，系统执行可控淘汰而非无限分配或崩溃 |
| AC-P2-009 | 层次化 LOD | 远近视角下能够选择不同细节层级，并可通过统计或调试手段验证 |
| AC-P2-010 | 数据规模 | 在基准硬件上打开并浏览至少 100,000,000 点的数据集 |
| AC-P2-011 | 帧率 | 1920×1080、持续相机运动场景中平均帧率不低于 30 FPS，目标为 60 FPS |
| AC-P2-012 | CUDA-Vulkan 零拷贝 | CUDA 结果经外部内存互操作直接供 Vulkan 使用，不经过 CPU 回读再上传 |
| AC-P2-013 | GPU 同步 | 验证层或诊断工具未报告由项目代码导致的资源生命周期及同步错误 |
| AC-P2-014 | 后端隔离 | UI 不直接访问 Vulkan 句柄，OpenGL 后端仍可独立启动 |
| AC-P2-015 | 性能报告 | 报告包含硬件、驱动、数据集、分辨率、平均 FPS、帧时间、内存和显存信息 |

AC-P2-011 的低帧率百分位阈值须在基准硬件确定后补充。在该指标补充前，平均 FPS 是当前明确的强制帧率指标。

## 8. 非功能需求

### 8.1 性能需求

#### NFR-PERF-001 数据规模

- Phase 1 必须验证至少 1,000 万点数据集；
- Phase 2 必须以至少 1 亿点数据集作为目标验收规模。

#### NFR-PERF-002 帧率

Phase 2 在 1920×1080 分辨率和持续相机运动场景下：

- 平均帧率必须不低于 30 FPS；
- 优化目标为平均 60 FPS；
- 具体基准硬件和低帧率百分位阈值待确定。

#### NFR-PERF-003 UI 响应

文件读取、数据解析、分块、GPU 上传和 Shader/Pipeline 准备等耗时任务不得长期占用 Qt UI 线程。

#### NFR-PERF-004 加载时间

当前不规定固定加载秒数。系统必须：

- 显示加载进度或明确的阶段状态；
- 保持 UI 响应；
- 支持取消；
- 在性能报告中记录实际加载时间及测试环境。

### 8.2 稳定性需求

#### NFR-REL-001 错误隔离

单个文件加载失败不得导致应用崩溃。失败后用户应能够继续选择其他文件。

#### NFR-REL-002 资源释放

以下场景必须正确释放 CPU、OpenGL、Vulkan 和 CUDA 资源：

- 正常卸载数据集；
- 用户取消加载；
- 后端初始化中途失败；
- 窗口关闭；
- 应用正常退出；
- 互操作注册或映射失败。

#### NFR-REL-003 可恢复错误

对于文件错误、可选 CUDA 不可用、Pipeline Cache 失效等可恢复问题，系统应保留基础操作能力，并向用户说明降级状态。

### 8.3 可维护性需求

#### NFR-MAIN-001 现代 C++

项目必须使用 C++17。

#### NFR-MAIN-002 RAII

堆内存、线程、文件、OpenGL 对象、Vulkan 对象及 CUDA 资源必须使用 RAII 或等效的确定性生命周期封装。

#### NFR-MAIN-003 智能指针

需要动态所有权时必须使用 `std::unique_ptr` 或 `std::shared_ptr`。不得使用裸指针手动拥有和释放资源。

非拥有型引用的具体表达方式由编码设计确定，但不得造成所有权不明确。

#### NFR-MAIN-004 头文件封装

公共头文件必须保持最小依赖和最小接口暴露。私有成员、辅助函数和实现类型必须隐藏在 `.cpp` 文件中，推荐使用 Pimpl 或无名命名空间。

#### NFR-MAIN-005 命名

- 类名使用英文 PascalCase；
- 函数和变量使用英文 camelCase；
- 禁止使用拼音命名；
- 成员变量命名风格必须在项目内保持统一。

#### NFR-MAIN-006 注释

- 函数声明处使用简短注释说明功能、参数和返回值；
- 简单实现内部不添加重复代码语义的注释；
- 复杂算法、同步或资源所有权转换必须在关键位置说明“为什么”。

### 8.4 可移植性需求

#### NFR-PORT-001 当前支持平台

当前强制支持平台为：

- Windows 10 64 位；
- Windows 11 64 位。

#### NFR-PORT-002 Linux 扩展能力

架构和 CMake 配置应避免无必要地绑定 Windows 专用实现，为未来 Linux 支持保留扩展能力。

Linux 不属于当前阶段强制验收平台。

#### NFR-PORT-003 无 CUDA 降级

基础 OpenGL/Vulkan 渲染应能够在 CUDA 功能关闭时运行。CUDA 加速及互操作功能仅在兼容 NVIDIA GPU 和运行环境下启用。

### 8.5 可测试性需求

#### NFR-TEST-001 可重复性能场景

性能测试必须记录：

- 测试数据集及点数；
- 数据属性；
- 运行后端；
- 窗口分辨率；
- 相机运动或视图测试路径；
- CPU、GPU、内存；
- 操作系统、驱动和相关运行库版本；
- 构建类型和关键配置。

#### NFR-TEST-002 诊断能力

开发或测试构建应提供足以验证以下行为的诊断信息：

- 分块和可见性结果；
- LOD 选择结果；
- 显存驻留和淘汰；
- Vulkan 命令录制线程参与情况；
- CUDA/图形互操作是否实际启用。

## 9. 技术约束

### 9.1 固定技术栈

| 类别 | 约束 |
|---|---|
| 编程语言 | C++17 |
| GUI | Qt 5.15.19 |
| Phase 1 渲染 | OpenGL 4.5 |
| Phase 2 渲染 | Vulkan |
| GPU 计算 | CUDA |
| 图形数学 | GLM，数学库仅限 GLM |
| 点云 I/O | PCL 仅用于 I/O 读取 |
| 构建系统 | CMake |

### 9.2 禁止事项

项目不得：

- 使用 PCL 承担渲染实现；
- 将 Engine 设计为 Qt UI 对象；
- 向 UI 暴露 OpenGL/Vulkan/CUDA 底层资源句柄；
- 在头文件中放置不必要的实现细节；
- 使用裸指针手动管理资源；
- 使用旧式 OpenGL 固定功能管线；
- 将 CPU 回读再上传描述为 CUDA-图形 API 零拷贝；
- 在没有明确新增需求的情况下扩展到深度学习、复杂 GIS 坐标转换或网络下载。

### 9.3 后端共存约束

最终项目必须保留 OpenGL 与 Vulkan 两个独立后端，并满足：

- 可在启动时选择；
- 使用统一 Engine 上层接口；
- 不要求运行时热切换；
- 一个后端的初始化失败不得破坏另一个后端的代码独立性；
- 公共业务逻辑应尽量复用，底层 API 对象不得跨后端泄漏。

## 10. 硬件与软件环境

### 10.1 最低功能环境

基础渲染环境应满足：

- Windows 10/11 64 位；
- 支持 OpenGL 4.5 的 GPU 和驱动，用于 Phase 1；

- 与项目构建配置兼容的 CUDA Toolkit 和驱动；

### 10.3 性能基准硬件（待确定）

用于判定 1 亿点和 30 FPS 指标的基准硬件尚未提供。后续必须补充：

- CPU 型号及核心/线程数量；
- GPU 型号及显存容量；
- 系统内存容量；
- 存储介质类型；
- 操作系统版本；
- GPU 驱动版本；
- CUDA Toolkit 版本；
- 显示分辨率。

在基准硬件确定前，不得将开发机上的偶然测试结果描述为普适性能保证。

## 16. 需求变更规则

发生以下情况时必须更新本文档，而不是直接在代码中自行决定：

- 新增 LAS/LAZ 或其他文件格式；
- 改变强制支持平台；
- 改变阶段数据规模或 FPS 指标；
- 引入 GLM、PCL 之外的新数学或点云处理依赖；
- 修改 CUDA 预处理范围；
- 修改“零拷贝”的定义；

- 新增复杂 GIS 坐标转换、网络数据或点云编辑功能；
- 根据参考源码确定相机交互方式。

每次需求变更至少应记录变更内容、原因、影响阶段和验收标准变化。
